# Developing Arogio Health

Use Node.js 22 and npm. Install the locked dependencies with `npm ci`, then copy `.env.example` to `.env` if it does not already exist. Keep existing local environment values.

## Run locally

```bash
npm start
npm run android
npm run ios
npm run web
```

`npm start` opens the Expo development server. With a development build installed, scan its QR code to connect. Use `npx expo start --go` when intentionally testing with Expo Go and its bundled modules. Android requires an emulator or device; the iOS simulator requires macOS.

On Windows PowerShell, use `npm.cmd` and `npx.cmd` if script execution policy blocks the `.ps1` launchers.

## Project structure

- `src/app/`: Expo Router screens and navigator layouts only.
- `src/features/`: Feature components, API contracts, hooks, and state.
- `src/services/`: Shared HTTP and secure token storage.
- `src/providers/`: App-wide providers.
- `src/config/`: Environment configuration.
- `src/lib/`: Shared library setup.
- `test/`: Node-based contract and service tests.
- `assets/`: App icons and image assets.

Add new screens under `src/app/` and keep reusable implementation outside that directory. Install dependencies with `npx expo install <package>` so Expo resolves compatible versions.

## Cloud builds

`eas.json` defines development, internal preview, and production profiles. Development builds include `expo-dev-client`; Android previews produce installable APKs.

Before the first build, sign in and link this checkout to your Expo project:

```bash
npx eas-cli@latest login
npx eas-cli@latest init
npx eas-cli@latest build --profile development --platform android
```

Use `--platform ios` for an iOS build. EAS will guide you through signing credentials; physical iOS device distribution requires the appropriate Apple account and registered devices. Configure `EXPO_PUBLIC_API_URL` and `EXPO_PUBLIC_GOOGLE_CLIENT_ID` in the matching EAS development, preview, and production environments. These public values are bundled into the app; never put secrets in `EXPO_PUBLIC_*` variables. Configure Google OAuth credentials and redirect URLs for each target platform before testing Google login.

For internal testing or store builds:

```bash
npx eas-cli@latest build --profile preview --platform android
npx eas-cli@latest build --profile production --platform all
```

Native projects are generated by Expo. Configure native behavior in `app.json` and config plugins rather than creating `android/` or `ios/` manually. Rebuild the development client after native dependency or config changes. EAS Update requires a separate `expo-updates` setup before publishing OTA updates.

## Before committing

```bash
npx expo install --check
npm run lint
npm run typecheck
npm test
```

GitHub Actions runs lint, typecheck, and tests on pushes and pull requests. Keep `.env`, signing credentials, generated native projects, and build outputs out of Git.
