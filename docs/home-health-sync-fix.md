# Home health cards and connected-app refresh

31 October 2026.

Home previously filtered out every metric without a current-day value, then returned no section when all were missing. Steps, Movement and Sleep now stay visible during initialization, missing readings and refresh errors. Real zero remains a real zero; missing values use `--` with a reason. Cards retain saved targets and source labels without combining manual, phone and connected-app totals. Narrow screens use two columns and icons cannot shrink out of view. Home now also shows the current time in IST beside its date.

Connected readings show a dated last-check time on Home and in Health apps. Each successfully read daily value carries its own `checkedAt`; values retained after a failed cell keep their earlier check time. These are read/check times, not claims about when the source sensor measured the value. An empty successful result clears earlier data for that cell; revoked grants and source changes also remove it. Partial failures show recovery instead of presenting the whole operation as successful. Foreground results now persist in the same per-owner/source secure cache even without background permission, and restored data is filtered through current selected types and granted access before display.

Health Connect supports grouped aggregation. The reader now uses one seven-day duration-bucket request per granted metric, reducing a full twelve-metric refresh from 84 aggregate calls to 12, plus the existing latest-weight query. Day buckets start at IST midnight and sparse results retain their correct dates. Requests are sequential by metric to avoid bursts. Native readers without grouped support retain the previous daily-request path. A queued resume/pull refresh is no longer cleared by the finishing older read, so the queued request can run next.

App discovery additionally checks installed Pebble Halo (`com.pebble.ring.app`) and Samsung Health (`com.sec.android.app.shealth`) packages if a permissions-rationale activity is not discoverable. An app still must declare supported Health Connect write permissions to be offered; names alone never prove data sharing. Missing read permissions on a selected app now have a Review access action. Source-specific instructions and Open app/Refresh readings controls help distinguish Arogio read access from the source app’s separate export/write access. No fallback silently imports another app’s data.

Pebble documents Health Connect support: https://www.pebblecart.com/blogs/wellness/we-heard-you-turning-community-questions-into-better-wellness. Samsung documents Samsung Health > Settings > Health Connect > App permissions > Samsung Health: https://developer.samsung.com/health/health-connect-faq.html. The wearable must sync into its companion app and that app must write the relevant data into Health Connect before Arogio can read it. A bridge app may be the actual writer; select that writer rather than substituting origins behind the user’s back.

Validation: lint/typecheck and 110 automated tests, including sparse weekly aggregation, zero/missing values, wrong-source rejection, partial-failure retention, permission filtering, foreground-cache isolation and actual rendered Home empty/cached states. The Android source-discovery module compiles. Synthetic 390px and 320px layouts were inspected. These checks do not establish physical Pebble or Samsung wearable delivery; compare today's exported records on a phone with the companion app before device acceptance.
