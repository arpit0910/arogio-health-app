# Structured provider directory integration

Home, Find Care, Doctors and Hospitals now read `/public/doctors` and `/public/hospitals` through `src/features/care-directory/providerCatalog.ts`. The client validates API responses, adapts them to shared care components, preserves server pagination and supports active department filters, hospital types and NABH filters. The doctor department picker reads `/public/departments`.

Cards and details use uploaded `image_url`/`image_alt` metadata. Only URLs on the configured API origin are accepted. Missing/broken images show the provider icon. No hospital name triggers a bundled stock photo. Detail screens display API qualifications, registration, council, experience, INR fees, hospital benefits and recorded practice schedules. Related-provider failures can be retried while the main record remains readable. Generic lab/pharmacy/medicine reads and directory corrections retain their existing APIs.

The Doctors/Hospitals migration and backend must be deployed before this app version. Upload and review provider photos in the backend admin portal. See `D:/arogio_health_backend/docs/PROVIDER_IMAGES.md`. This change does not publish a hosted backend, seed data, create a release APK or prove physical-device image loading. Standalone synthetic browser previews are generated by `scripts/preview-provider-catalog.cjs`.

Validation: project lint, typecheck and Node tests; provider contract tests are in `test/providerCatalog.test.ts`. The missing Profile route found by the full test run was restored using the existing protected account screen.
